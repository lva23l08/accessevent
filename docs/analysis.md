# Техническое задание: AccessEvent

## 1. Назначение и цели
AccessEvent — веб-платформа для организации мероприятий с акцентом на доступность для людей с нарушениями слуха.
Цель: обеспечить полный доступ к информации о мероприятиях без необходимости слышать.

## 2. Описание предметной области
Система работает с сущностями: Event, Participant, Organizer, Registration, Notification, Review, Category.
Основные процессы: создание мероприятия, регистрация, визуальные уведомления, чат, отзывы.

## 3. Требования к функциям
- FR-01: Регистрация и авторизация пользователей
- FR-02: Создание мероприятий организатором
- FR-03: Регистрация на мероприятие
- FR-04: Отмена регистрации
- FR-05: Просмотр списка мероприятий
- FR-06: Фильтрация мероприятий (инклюзивные/обычные)
- FR-07: Визуальные уведомления о начале мероприятия
- FR-08: Цветовая индикация статуса регистрации
- FR-09: Текстовый чат на странице мероприятия
- FR-10: Загрузка материалов мероприятия
- FR-11: Отзывы на мероприятия
- FR-12: Редактирование мероприятия организатором
- FR-13: Отмена/перенос мероприятия
- FR-14: Панель администратора (модерация, бан)
- FR-15: Статистика для владельца платформы

## 4. Требования к качеству
- NFR-01: Время отклика системы < 2 секунды
- NFR-02: Поддержка PostgreSQL 14+
- NFR-03: Python 3.10+, Flask 2.3+
- NFR-04: Соответствие WCAG 2.1 AA (доступность)
- NFR-05: Адаптивный дизайн (mobile-first)
- NFR-06: Пароли хранятся в хешированном виде (bcrypt)
- NFR-07: Защита от SQL-инъекций (через SQLAlchemy ORM)
- NFR-08: Контейнеризация через Docker (GHCR)

## 5. Требования к интерфейсу
- Адаптивный дизайн (mobile-first)
- Соответствие WCAG 2.1 AA
- Цветовая индикация статусов
- Визуальные уведомления (баннеры)
- Текстовый чат
- Шрифт минимум 16px, высокая контрастность

## 6. Требования к данным
- БД: PostgreSQL 14+
- ORM: SQLAlchemy
- Минимум 7 таблиц
- Пароли хешируются (bcrypt)

## 7. Технологический стек
- Язык: Python 3.10+
- Фреймворк: Flask 2.3+
- БД: PostgreSQL 14+
- Шаблоны: Jinja2
- CI/CD: GitHub Actions + GHCR
- Тесты: pytest

## 8. Ограничения и допущения
- В текущей версии нет мобильного приложения (только веб)
- Нет интеграции с платёжными системами
- Нет функции видеоконференций
- Развёртывание через Docker
- Срок разработки: 6 дней (36 часов)
